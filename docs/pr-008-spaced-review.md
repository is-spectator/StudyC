# PR-008：闪卡间隔复习与到期队列

日期：2026-11-24。状态：开发任务书，尚未实现。所属仓库：`is-spectator/StudyC`。建议分支：`codex/studyc-spaced-review`。

## 1. 要解决的问题与交付结果

PR-006 已经能保存卡片、自由翻卡和自评，但不知道哪张应该再次复习。本 PR 让用户在卡组中看到「新卡」「现在到期」数量，开始一轮最多 20 张的复习，翻面评价后保存下次时间，并能在刷新或重新登录后继续。

**一条完成路径**：打开卡组 → 看见 2 张新卡 → 开始复习 → 第一张选「基本记住」，显示 1 天后 → 退出并刷新 → 继续第二张 → 最后一张保存成功 → 显示本轮有效复习 2 张；到期前不重复出现在到期队列，到期后重新可选。

基线为已合并 PR-001～007 的 `codex/studyc-independent-backend`（核对时 `4feb94d`）。发布前的本地验收基线还须包含问答修复 [GitHub #8](https://github.com/is-spectator/StudyC/pull/8)；该修复没有数据库迁移，与本功能相互独立。GitHub #8 不等于功能包 PR-008。

## 2. 固定范围

- 学习集内的卡组列表显示各卡组新卡数和现在到期数；详情显示下一次到期时间、继续未完成复习与开始新一轮入口。
- 每轮限同一卡组，最多 20 张；先到期、再新卡。队列固定，内容和来源使用开始时的不可变快照。
- 复用现有问题/答案、来源查看、四档自评和账号隔离交互。翻面后才能通过正常 UI 评级。
- 每张评价都保存到服务端，明确返回下一次复习时间；记录保存成功才前进。
- 旧「自由翻卡」和新「到期复习」是两个清楚命名的入口，各有会话/统计。新卡来源可以是手动创建或 AI 生成保存，二者规则一致。
- 全部新流程可用手动卡完成，无 AI 调用或新供应商配置。

本包不包括：跨卡组混合练习、每天配额、卡片停用、通知、连续打卡、掌握百分比、自动计划、全局复习首页、填空自动判分、FSRS、音视频卡。退出页面只中断操作，不暂停到期计时。原资料变更而卡片正文未变，不重置该卡调度。

## 3. 调度契约：`studyc-srs-v1`

这是 StudyC 的可解释 v1 产品规则，不声称复刻 StudyFetch 的隐藏算法，也不承诺长期记忆效果。原站 A07 只验证过一次 Easy 评级与推进，没有跨天验收其调度规则。

### 3.1 时间与新卡

- `dueAt`、`reviewedAt` 存 UTC 时间点；资格只由服务端 `dueAt <= now` 判断。1 天固定为 24 小时，10 分钟固定为 600 秒。评级事务取得必要锁后只采集一次服务器时间，用同一值保存事件、reviewedAt 和计算 dueAt；不能直接用可能早于锁等待的事务开始时间代替实际评级时间。
- 客户端只提交评级，不接受客户端的时间、下次间隔、阶段或到期时间。服务实现可注入测试时钟；不得新增可由外部请求调整时钟的接口。
- 页面按设备时区显示「下次复习」，时间展示注明时区；设备时区变化不改变到期资格。首版使用「现在到期」，不把今天晚些时候才到期的卡提前算进去。队列/卡组摘要的 `nextDueAt` 是当前有效卡版本中严格晚于服务端 now 的最早到期点，没有则 null；已经到期和新卡分别计入 dueCount/newCount。
- 没有调度行，或行中的 `cardVersion` 不等于当前卡片版本，均逻辑上算新卡。已有 PR-006 的自评事件继续保留，不据此倒推调度。
- 正反面编辑导致卡片版本增加时，当前版本重新算新卡；旧调度/旧事件保留作历史。卡组改名不影响调度。若只是重新保存相同文本却仍增加版本，也按版本变化处理，编辑页需说明。

### 3.2 固定阶梯

稳定间隔为 `[1, 3, 7, 14, 30, 60]` 天，对应阶段 `0…5`。新卡及「还没记住」后的重学阶段为 `-1`。只有内容版本相同的现有调度可以带入原阶段；新版本从 `-1` 起。

| 自评值 / 文案 | 新阶段 | 从本次服务端保存时间算起的间隔 |
| --- | --- | --- |
| `again` / 还没记住 | `-1` | 10 分钟 |
| `hard` / 有些吃力 | `0` | 1 天 |
| `good` / 基本记住 | `min(原阶段 + 1, 5)` | 新阶段对应天数 |
| `easy` / 很熟悉 | `min(原阶段 + 2, 5)` | 新阶段对应天数 |

例：新卡选 good 为 1 天；下次 good 为 3 天；再下次 easy 为 14 天。新卡选 easy 为 3 天。任意阶段选 hard 回到 1 天，again 为 10 分钟；已处于 60 天时 good/easy 仍为 60 天。过期多久不改变规则，不以旧 `dueAt` 加间隔，避免复习完仍立即过期。

一次会话内每张卡最多有效评价一次；again 不插回本轮队列，10 分钟后在下一轮出现。规则版本与评价前后状态一并保存，未来换算法必须另建迁移/兼容方案。

## 4. 队列、恢复、编辑与并发

### 4.1 开始一轮

1. 核验当前账户、学习集、卡组。取服务端开始时间作为本轮候选判断点。
2. 到期卡按 `(dueAt, cardId)` 升序；新卡按 `(position, cardId)` 升序；拼接后取前 20 张。两类互斥，版本变化的卡只算新卡。
3. 冻结实际选中的卡片、版本、引用、有效阶段（新卡为 -1）以及 `expectedScheduleRevision`。不存在调度行为 null；即使因内容版本变化被视为新卡，也要记录已有调度行的真实 revision，不能一律写 null。
4. 队列为空返回 `409 no_cards_due`，不创建空会话。将该码纳入后端错误类型/状态映射；前端收到后重新 GET review-queue 获取当前计数和下次时间，不依赖现有共享认证客户端会丢弃的 error.details。GET 展示候选不占位，只有 POST 开始才建立会话。
5. 幂等开始请求重放返回同一会话，不能按后来已变化的队列重新生成。不同请求允许独立会话；UI 优先提供继续未完成会话，另开一轮需要明确点击。跨窗口重叠由提交时的版本检查处理。

开始后新增卡、后来才到期的卡留到下一轮。显示「本轮 N 张」与「当前剩余待复习」时分开计算，完成一轮不等于所有内容已复习完。

### 4.2 逐张推进

同一事务内先检查账户归属和请求幂等记录，再锁定会话/当前卡及调度状态，校验会话版本、位置、cardId，然后执行以下结果之一：

| 条件 | 结果 | 是否推进调度 |
| --- | --- | --- |
| 内容版本与开始时一致，schedule revision 也一致 | `reviewed`：保存有效评级、调度前后状态和下一次时间 | 是，更新/插入一次 |
| 内容版本已经变更 | `skipped`，原因 `card_changed` | 否，新版本仍是新卡 |
| 内容版本相同，但调度 revision 已被另一轮更新 | `skipped`，原因 `already_reviewed` | 否，保留另一轮结果 |

每个结果都保存不可变推进记录，并将本轮位置向前推进一次；结束页分别统计「有效复习 X 张」「跳过 Y 张」。跳过不是错误评级，也不算有效复习。最后一张失效仍能通过明确的跳过动作结束，不把用户困在旧队列中。

读取会话可返回当前卡的失效原因供 UI 提示；GET 不写入跳过记录。显示「卡片已修改，跳过后请复习新版本」或「已在另一轮复习」。客户端执行显式 `skip_stale` 推进；若从读取到提交之间才失效，`rate` 也必须原子返回上述 skipped 结果，而非给新版本调度。正常未失效卡不能用 `skip_stale` 静默略过，返回 409 并允许重新读取。

相同 `clientRequestId` 和原摘要重放必须返回原始 outcome 与原下一次时间，并带当前会话进度；它优先于当前版本判断，不能把已成功的重试误报为跳过。同 ID 不同内容返回 `409 idempotency_conflict`。两个会话同时评级同一张卡，只能有一个有效调度，另一个得到明确跳过。

### 4.3 旧模式与指标

旧自由翻卡继续使用 PR-006 的冻结快照；即使卡片后来编辑，旧会话仍按既有规则完成。它的自评不推进 SRS。旧卡组「累计自评次数」继续只读旧表，新区域显示到期复习有效次数、四档分布和下次时间。首版不做跨模式合计，不把评级、有效次数或队列完成率命名为客观正确率/掌握率。

## 5. 数据与迁移

建议独立增加三类表；最终字段名可调整，契约不可省略：

| 表 | 必须保存的内容 |
| --- | --- |
| `study_flashcard_schedules` | cardId、归属、当前卡片版本、规则版本、阶段、dueAt、lastReviewedAt、单调递增 revision。每张卡一行当前状态；旧状态在事件里。 |
| `study_spaced_review_sessions` | 归属、卡组、请求 ID/摘要、实际队列与资料/卡片快照、规则版本、当前位置、version、in_progress/completed、创建/更新时间。 |
| `study_spaced_review_actions` | 归属、sessionId/position、请求 ID/摘要、reviewed/skipped 与原因、有效评级、服务端时间、卡片版本、预期 revision、调度前后快照、原始返回结果。 |

约束：开始请求 ID 在 sessions 内按账户唯一，推进请求 ID 在 actions 内按账户唯一，不要求跨两类请求共享命名空间；摘要包含操作类型、所属集/组/会话与规范化原始请求字段。同 session/position 只推进一次；调度 revision 单调增加，即使卡片改版也不归零。账号注销写保护、删除级联、会话/卡组/学习集归属在全部接口一致。用于 owner/dueAt 查询的索引只建在新表上。调度事务可复用 `Db.tx(fn, user)` 的账号级锁，但仍必须核验 revision，防止依次到达的旧会话重复推进。

当前最高迁移为 v6，单独开发时新增 v7；若其他功能先合并，应重排新迁移编号。**不修改 v1～v6 的 SQL/checksum/fingerprint，不给旧 session 增加 mode，不给旧 cards 顺手新增列、索引或 UNIQUE。** 当前迁移器会对旧表结构完整复核，这些变更会破坏已有库校验。

`study_flashcards` 仅有全局 id 主键，没有 owner/set/deck 复合唯一键。可以只保存 cardId 并通过父卡派生归属，或使用 cardId 外键配合新表的归属一致性守卫；必须证明不能把 A 的卡挂到 B 的调度。新增守卫函数若承担约束，也纳入迁移核验。所有写入只取服务端已验证的归属和快照。

首次升级不回填历史评级，不预填未来学习结果；无调度行自然作为新卡读取。重复迁移与 check 都应成功；带脏旧结构的库仍应拒绝迁移。当前严格版本检查使旧 v6 应用不能直接读取 v7 迁移登记，回退应使用**仍识别新 schema 的功能关闭版本或开关**，保留新表和记录。关闭时服务端拒绝所有新 SRS 写入，UI 隐藏新入口，已有直链显示功能关闭并可返回卡组；旧自由翻卡继续可用。仅隐藏按钮不算关闭能力，不能把“切回旧提交、保留数据库”写成未经验证的回滚方案。

## 6. API 与页面契约

前缀仍为 `/v1/study/sets/:setId/flashcard-decks/:deckId`。复用 Cookie、Expected-User、Origin/CSRF、共享写限流和 `private, no-store`。JSON 上限维持 32 KiB。开始请求不得直接提交队列、卡片正文或计划间隔。

| 方法与路径 | 输入 / 输出 |
| --- | --- |
| `GET /review-queue` | 返回新卡数、现在到期数、nextDueAt、服务端时间、最近未完成到期会话摘要；预览最多 20 张且不建立会话。 |
| `POST /review-sessions` | `{clientRequestId}`；服务端选卡，返回新会话 201，原请求重放 200。 |
| `GET /review-sessions/:sessionId` | 恢复固定队列/位置与当前卡失效状态；仅本人可读。 |
| `POST /review-sessions/:sessionId/actions` | `{clientRequestId,version,position,cardId,action,rating?}`；action 为 rate 或 skip_stale，只有 rate 需要四档 rating；返回原 outcome、nextDueAt（如适用）与最新会话。新推进 201，幂等重放 200。 |

前后端开工前固定以下最小响应 DTO，不靠两边分别推测：

- 队列响应：`{serverNow,newCount,dueCount,nextDueAt,lastSession,candidates}`；candidates 最多 20 项，含 cardId、cardVersion、new/due 分类；不必在列表回传全部来源正文。
- 开始/恢复响应：`{session}`。session 含 `schemaVersion:1`、`mode:"spaced_review"`、id、studySetId、deckId、status、version、ruleVersion、nextIndex、cards（固定顺序/内容/引用/卡片版本/effectiveStage/expectedScheduleRevision）、sourceSnapshots、reviewedCount、skippedCount 和 current。
- current 为空表示已完成；否则包含 cardId、position、staleReason 以及服务端计算的 `ratingIntervalsSeconds:{again,hard,good,easy}`。该间隔由快照中的有效阶段与规则版本计算，失效卡返回 null 并显示跳过提示；前端不自行再实现一套算法。
- 推进响应：`{outcome,session}`。outcome 含 kind、reason（正常评级为 null）、cardId、position、appliedRating（跳过为 null）、occurredAt、nextDueAt（跳过为 null）。幂等重放保留原 outcome，session 可为最新进度。必须满足 reviewedCount + skippedCount = nextIndex。

卡组列表可增添每项 `reviewSummary`，单独字段表达 newCount、dueCount；卡组详情中的旧 `lastSession` 与旧 metrics 不改变语义。若页面展示学习集总数，必须从全部归属卡组查询，不能把当前 50 条分页相加当全量；首版只要求各卡组计数。

复习 URL 使用独立参数，例如 `/platform/studyset/:setId/flashcards?flashcardDeck=:deckId&spacedReviewSession=:sessionId`。不得与旧 `flashcardSession` 混用；同时出现两个模式参数属于无效路由组合，显示可恢复的入口，不静默选错会话。

前端必须覆盖：加载、空卡组、暂无到期、待保存、保存失败且可原请求重试、版本冲突且可重读、卡片失效、已完成。账户/学习集/卡组切换后旧响应不可更新新页面；按钮禁用不代替服务端幂等校验。四档按钮显示预计间隔，保存后以服务端实际 nextDueAt 为准。
