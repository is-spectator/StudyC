# PR-015：学习集回收站

第一版按整个学习集软删除/恢复，保存所有原对象 ID、原文、来源文件、生成快照、学习历史、计划和归类。没有永久删除或自动清理。侧栏「回收站」可恢复，学习集页「管理回收站状态」可明确移入。

迁移 v13 新增独立生命周期与请求表，原表和历史迁移不改写。未操作过的学习集生命周期版本为 0；移入/恢复逐次加一，恢复后保留版本，防止旧页面覆盖。请求带 clientRequestId，成功响应丢失可原意图重试；旧移入请求在后来恢复后只返回当前状态，不再次删除。409 保留意图、显示云端状态，需要读取最新状态后重新决定。

API：GET `/v1/study/trash`（20 条 UUID 分页），GET/PATCH `/v1/study/trash/:setId`。PATCH `{clientRequestId,version,deleted}`；16KiB 上限、同源 Cookie/Expected-User/Origin/CSRF、写限流。代理增加两组路径三种方法，不改变 Clyna/PlanPlan。

列表、文件夹计数/内容、搜索的全部分支、关联日历的读取/冲突查询都过滤回收站。资料、原文件下载、闪卡、复习、测验、错题、笔记、计划、对话、生成的服务层统一检查父学习集。事务中用学习集行 SHARE 锁；软删除用 UPDATE 锁并在等待锁后另查生命周期，避免旧快照跨越删除。启动必须有完整迁移，缺少生命周期表不降级放行。

软删除与取消任务在同一生成事务锁中完成。排队尝试记 not_sent 并释放 token 预留；运行尝试由原 worker 感知取消，已发送/未知用量不虚假退款，晚到成功只更新实际用量，不发布结果。恢复不会重启任务，需要明确手动重试。完成的内容和历史完整保留。恢复保留归类；若原文件夹期间被删除，则恢复到未分类。

`STUDYC_TRASH_ENABLED=false` 保留查看，拒绝移入/恢复。回退保留 v13 数据并使用识别 v13 的应用。

本地 Chrome/Playwright（Browser plugin not available）已验证实际成功 PATCH 响应丢失后表单冻结与同意图重试、子资料 404、搜索隐藏、恢复原 ID/原文完全一致、侧栏列表刷新、手机 390×844 无横向溢出。验收样例保留在账户 A，标题「回收站完整流程 …」。截图和脚本位于 `/tmp/studyc-pr015`，不入库。后端覆盖归类、旧请求、账户隔离、只读关闭、v12 升级、日历隐藏、任务取消与用量，以及 HTTP 边界；前端和部署回归与前后端构建执行通过后提交。
