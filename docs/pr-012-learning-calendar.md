# PR-012：学习日历、时区与明确冲突确认

2026-11-24。分支 `codex/studyc-learning-calendar`，基于 PR-011 的最终修复提交 `6abcb38`。StudyC 独立前后端，未发布生产。

## 用户流程

全局侧栏「学习日历」提供日/周视图、日期切换、上一/下一时段、今天及分页。可创建学习时段、考试安排、手动事件，保存名称、说明、全天日期或具体时段。编辑、取消和恢复后刷新保留；页面日期/视图在URL中恢复。

计划任务「安排到日历」显式关联该任务。重复进入打开已有日程，不重复创建；同一任务仅有一条未取消日程。任务改期不会擅自移动日程。取消任务会暂停显示其日程并从冲突计算排除；恢复任务重新启用原安排，日历仍会提示已显示安排的重叠。日程自身取消不取消任务；已取消日程可以恢复，但不能覆盖后来创建的同任务有效安排。

没有重复事件、自动排程、提醒、外部OAuth/同步、邮件/推送或自动创建考试作答。日历中的考试仅是时间安排，不代替已提交测验作为学习完成依据。

## 时间与冲突口径

- 全天事件只存浮动公历日期 `YYYY-MM-DD`，改变账户时区不会换日；一次全天事件对应一个日期。
- 定时事件使用IANA创建时区、明确偏移的开始/结束输入，以及对应的绝对UTC时刻。保留原始本地时间/偏移快照，改变显示时区只转换展示，不移动实际时刻。
- 用户修改显示时区可输入合法IANA名称；默认UTC。本地验收最终设为Asia/Shanghai。设置独立于Clyna账户资料，不修改其他产品的时区。
- UI按分钟输入。不存在的本地时刻无可选项，不能保存；重复小时返回多个合法偏移，必须明确选择较早/较晚一次。不会默默把缺失时间推到下一小时。单次时段必须正时长且最长7天。
- 每个自然日的实际边界通过IANA规则求解，支持23/25小时、缺失午夜和整日跳过。被跳过日期仍可有浮动全天记录，但不会错误纳入跨越该日的定时事件。午夜结束采用右端不含的区间。
- 日程按查看时区分到日/周，已加载安排按全天优先、实际时间排序；跨日标签带日期，偏移变化的重复小时标签显示两种偏移。分页20条，可继续加载；查询范围最多42个自然日。
- 保存前可检查冲突，冲突包含同账户有效定时重叠和实际相交的全天安排。需勾选「知晓这些冲突，仍保存」；服务端再次核验所见对象ID/版本、时区和提议时间。检查后另一安排修改/取消导致确认过期，必须重新确认。不会自动挪动或取消其他安排。
- 冲突是提醒，允许用户明确保留重叠。一次冲突预览最多100项，超过则要求缩短时段，不能只展示部分却宣称已经全部确认。

## 数据与API

迁移v11 `studyc_learning_calendar`新增 `study_calendar_settings`、`study_calendar_events`、`study_calendar_requests`，包括同账户活动任务唯一索引、时间区间约束、有效账户写守卫和删除级联。保留v1～v10 SQL/checksum/fingerprint及历史数据。写操作按账户事务串行，带请求ID；相同请求重试不重复创建或重复改动。修改另带版本，409保留双方内容，由用户比较后明确保存。

所有API位于 `/v1/study/calendar`，沿用Cookie、Expected-User、Origin/CSRF、共享限流和private/no-store。写入JSON上限16KiB。新增6组Nginx路径、9种方法组合，其他产品代理保持不变。

| 路径 | 方法 | 契约 |
| --- | --- | --- |
| `/settings` | GET/PATCH | 读取 `{timeZone,version,enabled}`；写 `{clientRequestId,version,timeZone}`，首次预期版本0。 |
| `/time-options` | GET | local为`YYYY-MM-DDTHH:mm`，timeZone为IANA名称，返回零/一/多个明确偏移选项。 |
| `/task-event` | GET | studySetId/planId/taskId，返回当前账户所属任务及其唯一未取消日程。 |
| `/events` | GET/POST | from/to/cursor分页；创建 `{clientRequestId,title,description,kind,time,sourceTask?,acknowledgeConflicts?}`。 |
| `/events/:eventId` | GET/PATCH | 当前日程；修改带预期version、完整可编辑字段和cancelled，不允许改绑来源任务。 |
| `/conflicts` | POST | 预览完整候选，可传owned eventId排除自身，返回冲突列表与确认摘要。 |

`time`为`{kind:'all_day',date}`或`{kind:'timed',start,end,timeZone}`；start/end必须包含与IANA规则匹配的偏移，不接收不存在的当地时刻。服务端计算UTC时刻，客户端不能自行注入快照或覆盖来源。来源任务必须同时匹配账户、学习集和计划。

`STUDYC_CALENDAR_ENABLED=false`拒绝新建、编辑及设置修改，既有日程、设置和来源仍可查看。回退保留表，使用仍识别v11的应用；不能直接用v10应用启动v11库。
