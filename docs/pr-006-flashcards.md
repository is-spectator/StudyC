# PR-006：闪卡与自评学习

用户可以在同一个学习集中保存多套闪卡，手动维护问题与答案，或选择已保存资料生成一套候选卡片。生成任务完成后需要点击“保存为闪卡组”，才会创建卡组。生成失败、取消、中断不会显示成已保存。

## 页面与行为

`FlashcardsPanel({studySetId,materials})` 挂在学习集的闪卡入口，复用真实 `useAuth().request`。卡组列表支持继续加载；可以创建、重命名、查看卡片并编辑。编辑采用版本检查，409 时同时保留用户输入和云端内容，选择保留输入后仍需再次明确保存。

“从资料生成”选择1–5份资料及其当前版本、语言和1–20张卡。调用现有生成任务接口 `kind=flashcards`，展示状态及候选内容。手动卡片没有资料引用；生成卡片可以展开原文引用、资料版本、可确认的原PDF页码及生成时的完整资料快照。手动编辑生成卡后，页面注明引用仍是原生成出处，未验证修改后的表述。

开始学习会复制当时的全部卡片内容、版本及引用到独立会话。之后的卡片编辑不会改变正在进行的练习。每张卡先显示问题，翻面后才提供“还没记住 / 有些吃力 / 基本记住 / 很熟悉”四种自评。服务器保存事件和推进进度在同一事务中，收到成功响应后页面才前进；最后一张也必须先保存再显示完成。

学习会话由云端保存。URL使用 `flashcardDeck` / `flashcardSession` 查询参数恢复同一会话；卡组详情也可继续最近未完成的一轮。统计为累计自评次数、各自评分布、最近学习时间，不称为正确率或客观掌握率。

账号或学习集变化会重新挂载整个界面，旧请求被取消，迟到结果不会写入新界面。切换卡组也会取消前台请求并递增选择版本，旧卡组迟到的开始学习响应不能改变当前卡组；开始请求的重试ID按卡组隔离。未保存的卡片编辑有离开与刷新提示。创建/生成/自评在请求结果不确定时保留原请求参数以便重试；物化接口另外按生成job唯一性去重。

## API

所有路由在现有 Cookie、Expected-User、Origin/CSRF 认证之后注册；POST/PATCH使用共享写操作限流。

| 路径（前缀 `/v1/study/sets/:setId/flashcard-decks`） | 方法 | 作用 |
|---|---|---|
| `/` | GET / POST | 卡组分页 / 手动创建 |
| `/:deckId` | GET / PATCH | 内容、续学会话、自评统计 / 重命名 |
| `/:deckId/cards` | POST | 幂等创建手动卡片 |
| `/:deckId/cards/:cardId` | PATCH | 带version编辑 |
| `/materialize` | POST | 将已成功的flashcards job显式保存为卡组 |
| `/:deckId/sessions` | POST | 幂等开始一轮，冻结卡片快照 |
| `/:deckId/sessions/:sessionId` | GET | 恢复当前进度 |
| `/:deckId/sessions/:sessionId/reviews` | POST | 幂等提交自评，校验会话version/cardId/position |

创建使用 `clientRequestId`；相同请求重放返回200，新建返回201；重用ID但改内容返回409。物化事务校验job所属账号/学习集、kind、成功状态、数量和所有引用，并将不可变输入快照复制到卡组。重复物化同一个job不会产生第二套卡组，即使请求ID不同；额外请求ID仍登记，之后不能绑定其他job。

卡组名称最多160字符，每套最多200张手动卡，问题最多2000 UTF-8字节、答案最多8000字节。列表按稳定UUID游标分页，每页50套，不批量发送资料正文；详细页返回实际快照。请求体上限32KiB。

## 数据与隔离

新增v5 SQL来自 `server/src/db/flashcards-schema.ts`，导出 `FLASHCARDS_SCHEMA_SQL` 与 `FLASHCARD_TABLES`，不修改历史迁移。五张表分别保存卡组、卡片、会话、自评事件、物化请求记录。账号、学习集、卡组/会话使用复合外键与查询条件绑定；账号删除级联清理，所有写表使用共享active-user触发器。所有业务读写先验证账号仍有效。

学习会话卡片快照和卡组资料快照仅创建时写入，没有更新它们的HTTP入口。自评事件是学习者的主观标记，不做自动答案判分，也没有间隔重复算法。本PR没有自动邮件、外部AI直调或密钥读取；AI通过已有生成服务执行。
