# PR-002：云端学习空间与文本编辑

StudyC 仓库内的前端接入，基于 PR-001 独立后端。分支 `codex/studyc-cloud-workspace` 从 `97adfc6` 开始；业务后端与数据库结构不变。前端保留原有米色内容区、深色导航和卡片视觉。

## 可执行流程

- 登录后读取当前账户的真实学习集，支持同名创建、改名和分页。
- `/platform/studyset/:studySetId` 只加载该集合资料；`/material/:materialId` 使用完整父子 ID 打开纯文本编辑器。
- 新建、修改、刷新恢复、跨设备读取由八个已部署 API 提供。明确区分加载、未保存、保存中、云端已保存、失败与冲突状态。
- 资料问答、闪卡、练习和计划等未接入的工具显示当前状态；不会拿旧示例冒充所选云端学习集的内容。
- `/platform`、`/platform/studysets`、旧 `main` 和引导入口显示云端列表，不自动选择第一份资料。

## 数据与身份边界

所有请求使用同源 Cookie、Expected-User 与 CSRF。401/账户不符才清除已确认身份；CSRF 失效复核同一账户，业务网络错误/5xx/版本冲突留在业务页面。取消请求保持 AbortError，账户 epoch 和实体加载代次拒绝迟到响应。保存请求不会自动重放。

每次创建保留 `clientRequestId` 和原始提交意图，未知结果时用相同意图重试。POST 重放可能返回已被另一端修改的当前资料，此时编辑器保留冲突，不能默默把旧草稿基于新版本覆盖。PATCH 只有在读回精确下一版本且内容匹配时，才确认上次丢失响应的保存成功。

草稿同步写入当前账户的本机命名空间，不作为云端已保存的依据。每个活跃编辑器使用独立 writer；保存清理只删除自己记录及仍未改变的恢复来源，其他标签页的新修改保留。重新打开同一资料可恢复最新未清理的本机草稿，未承诺永久按标签页绑定。存储失败有明确提示与下载出口，不能无声丢失草稿。

损坏草稿暂停编辑并保留原始记录；导出后，由用户明确选择清理。损坏记录在另一处变化时，旧页面不能清除它。`/platform/local-data` 分开显示旧版记录和未同步草稿，导出同时保留解析内容与逐字原始字符串。旧数据不自动上传、不凭名称猜测学习集归属、不自动删除。

409 冲突并排保留我的草稿与云端版本。选择“保留我的草稿继续编辑”只更新编辑基线，用户还须明确保存；“使用云端版本”才丢弃当前草稿。离开未同步编辑有提示；接受离开立即取消当前保存回调，防止迟到成功把页面带回去。

`npm test` 覆盖认证、API、账户存储、草稿与路由；`npm run build` 检查类型并构建。现有 `server/` 独立测试和 CI 保留，新增前端 CI。

Vite 本地 `/v1/study/` 转发 8790，账户 `/v1` 转发 8789。开发代理不放宽 Cookie、Origin 或 CSRF；浏览器故障验收使用独立状态化夹具，生产验收使用真实服务器和合成测试账户。

本次只切换 StudyC 静态版本，沿用已验证的 Nginx 8790 业务路由。不能重新生成默认关闭学习 API 的旧候选；不切换 Clyna/PlanPlan 页面，不重启两个后端，不迁移数据库。保留上一静态版本 JS/CSS，支持已打开页面继续加载；故障回退静态 current 软链接。
