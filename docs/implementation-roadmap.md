# StudyC 实施路线与交接顺序

日期：2026-11-21。状态：[PR-001 / StudyC #1](https://github.com/is-spectator/StudyC/pull/1) 与 [PR-002 / StudyC #2](https://github.com/is-spectator/StudyC/pull/2) 已合并。PR-003 在本仓库增加文本型 PDF 上传与页码提取，尚未部署；OCR、AI 与其他文件类型仍未实现。

实施边界：StudyC 的前后端、业务迁移和 PR 统一在 `is-spectator/StudyC`；Clyna 继续提供共享账户体系。后端与前端交付边界分别见 [PR-001 任务书](pr-001-study-data-api.md)和 [PR-002 任务书](pr-002-cloud-workspace.md)。

第一版的目标是：**登录 → 建立独立学习集 → 保存自己的资料 → 基于资料问答、生成卡片和试题 → 保存每次学习结果 → 重开或换设备继续。** 后续再扩展复习计划、多媒体、辅导和集成。

前两个开发 PR 已拆成独立任务书并实现：PR-001 在 **StudyC 仓库的独立后端**建立学习集与文本资料 API，PR-002 在同一仓库接入页面。路线编号是本项目的交付编号，不是 GitHub 自动分配的 PR 号。

## 1. 依据与现状

| 依据 | 能证明什么 |
| --- | --- |
| [官方功能登记](../reference/studyfetch-feature-register-20261120.csv) | 256 条功能点、22 个模块的官方描述；不等于已逐项操作成功。 |
| [实测登记](../reference/studyfetch-executed-tests-20261120.csv)、[详细审计](../reference/studyfetch-functional-audit-20261120.md) | 31 组操作记录拆为 144 条检查：71 成功、56 仅见界面、14 异常、3 受限。成功仅覆盖记录中的样本和步骤。 |
| [StudyC 缺口审计](../reference/studyc-feature-gaps-20261120.md) | 2026-11-20 的历史基线：已有真实账户接入，学习功能主要是浏览器本地保存、内置内容或界面入口；不包含随后 PR-001/002 的实现。 |

旧版预览的学习集是名称数组，路由固定为 `/platform/studyset/main`；资料没有 `studySetId`，多种学习产物只保存最近一份。因此先建立业务对象和数据归属，再接生成服务。

PR-001/002 已把正式账户的学习集和纯文本资料接到独立后端：按 UUID 路由，支持列表、创建、改名、文本编辑与版本冲突处理。已保存内容以服务器为准，旧本机记录和未同步草稿可单独查看/导出；旧 `main` 入口回到云端列表。旧示例仅在显式开发预览中加载，正式账户的后续学习工具显示未开放。前端部署与验收记录见 [PR-002 任务书](pr-002-cloud-workspace.md)。

本规划的表结构、接口和实施顺序是 **StudyC 的设计决策**，没有声称获得 StudyFetch 的内部实现。OCR、实时语音辅导、专业题库质量、长期 SRS 效果、视频生成质量和第三方同步仍没有充分实测依据。

## 2. 产品约束

- 产品名 **StudyC**，助手名 **小C**；围绕资料、主题、目标组织，不限定 K12，学习阶段可选。
- 注册继续集中在 `clyna.ai`；StudyC 与 PlanPlan 复用既有账户数据库及服务器。学习业务建立独立表，不塞进 PlanPlan 的计划/模板对象。
- 继续使用同源 Cookie 会话。共用账户不意味着已经实现跨子域免登；本轮不新增账号体系或单点登录。
- 保留现有视觉基础，只改实现真实功能所需的状态、路由和交互。首屏承诺必须与当前可执行能力一致。
- 每个生成产物保存资料 ID、输入版本及配置；每次作答单独记录。覆盖、完成、首次正确率、最终得分、掌握度分别定义。
- 旧浏览器数据保留，不自动上传、不凭名称猜测归属。后续单独提供用户确认的导入流程。

## 3. 整体路线

| 阶段 | 交付包与依赖 | 阶段完成标准 |
| --- | --- | --- |
| **S1：学习空间与文本资料** | PR-001 后端（含同源 Nginx 代理）与 PR-002 前端接入、动态路由均已部署验收。 | 两个学习集有不同 ID；资料按集隔离；另一账户无法访问；刷新和另一浏览器登录能恢复；失败不显示已保存。 |
| **S2：文件与来源处理** | PR-003 原文件存储、PDF 文本解析、页码定位、处理任务/失败重试；先支持文本型 PDF。图片/扫描 PDF 的 OCR 单独排到 S5。 | 原文件与解析正文都能重开；解析状态持久化；扫描件明确提示暂不支持，不能以空正文假成功。 |
| **S3：第一版学习闭环** | PR-004 生成任务、输入快照、调用/用量基础；PR-005 资料问答与引用；PR-006 多牌组/卡片；PR-007 测验与考试、作答历史。依赖 S1/S2。 | 回答/题目来自选中的实际资料，引用可定位；题数和题型符合配置；每次尝试和断点可恢复，跨集不串内容。**完成此阶段后验收第一版。** |
| **S4：复习、组织与计划** | SRS 到期队列；高亮/收藏/错题；资料驱动笔记与阅读；主题/计划/手动日历；全局搜索、文件夹、删除/回收站、真实复制；本地资料导入。按子项分别开 PR。 | 复习到期和掌握度有记录依据；搜索能返回真实对象；计划和时区正确；导入/复制不会错配所有者或覆盖已有内容。 |
| **S5：识别、评阅与媒体** | OCR；自带评分标准的作业批改；音频讲稿/TTS/播放器；录音保存/转写/笔记；基于已有牌组的匹配游戏。依赖文件、任务、用量基础。 | 能实际识别、评分、播放、下载和重开；输出与所选资料对应；计分与实际事件一致；任务失败可恢复。 |
| **S6：教学与互动扩展** | 多轮文字辅导、引导式聊天、教学插件；更多游戏；再单独评估实时语音/屏幕辅导、生成学习工具。 | 学员的答案实际影响下一步教学；插件配置可保存和追溯；生成工具经过隔离运行和交互验收；明确私有、链接访问和公开的权限。 |
| **S7：分享、商业化与外部集成** | 可撤销分享、资料导入扩展、日历 OAuth/同步/提醒、订阅权益/支付、公开社区；视频生成、多端、iMessage 类助手按需求单独立项。 | 访客权限可验；同步与支付回调幂等；计费对应真实权益；视频确有可播放文件；外部能力有实际可用的接入渠道。 |

在 PR-005～007 开放 AI 调用前，由 PR-004 完成服务端用量记录、限额和失败处理；收费功能可以后置，成本控制不能后置。第一版范围内不承诺自动学习计划、全文件格式、完整题库、实时语音、视频、社区或支付。

### PR-002 已实现并验收的边界

1. `/platform/studyset/:studySetId` 和资料详情使用真实 ID。旧 `main` 路由进入云端学习集列表，不任意绑定第一份云端资料；提供明确的“本机旧数据”入口供查看/导出。
2. 只把 PR-001 已实现的功能接入云端。新云端学习集的未接入工具显示功能状态，不加载旧账户级示例并冒充该学习集内容。旧数据不清除，云端请求失败不静默改存 localStorage 并显示成功。
3. 纯文本编辑独立于旧富文本示例；保存正文、版本及未保存草稿。409 编辑冲突保留双方文本，由用户决定，不自动覆盖。
4. 请求/缓存键包含账户与学习集 ID，切账户或切集的迟到响应不得回填当前页面。注销清理内存，保留原有账户隔离和会话重新验证。
5. `AuthProvider.request` 已区分业务请求失败、主动取消和认证失败：业务网络错误/5xx 不清除身份，`AbortError` 保留取消语义；只有符合认证语义的失败才改变身份状态。同账户重新验证保留编辑状态，切换账户的迟到回复不得修改新账户数据。
6. 原计划由 PR-002 承接的 Nginx 边界已随 PR-001 独立后端发布：按**八条路由及方法**放行学习 API，只对资料写入提高请求体上限；未知 `/v1` 仍 404、错误方法仍 405，认证缓存和跨域规则不放宽。PR-002 沿用该配置，仅发布 StudyC 静态前端，不重新生成默认关闭学习 API 的旧代理候选。
7. 本地 Vite 开发和预览代理已更新：`/v1/study/` 指向独立 StudyC 8790，其他 `/v1` 指向账户服务 8789。开发代理不放宽 Cookie、Origin 或 CSRF，不把生产地址或服务端凭据写入浏览器构建。

## 6. 第一版发布门槛

- 使用两份从未放进内置题包、内容明显不同的中文材料，分别建立两个学习集；至少一份为文本型 PDF。不能只用已经包含答案的“线段计数”截图评估推理质量。
- 两个账户、两个浏览器验收资料隔离、授权访问、持久化和续做。所有已接入功能不依赖 localStorage 作为唯一数据源。
- 回答含可打开的原文来源；卡片与试题能追溯输入版本。修改资料后旧产物仍说明使用的是旧输入，不能默默改写历史。
- 校验题量、题型、每次作答、评分分母、最后一道题和恢复进度；空资料、断网、超时、限额、部分失败均有明确状态。
- 原有 Clyna 注册、登录、退出及 PlanPlan 业务回归通过；新增功能上线不能扩大另一产品的 API 暴露范围。
- 每个 PR 附可执行验证、样例数据、接口/迁移说明与回滚方法。构建通过不能代替业务验收。

## 7. 协作与交接

PR-001 后端与 PR-002 前端均已部署验收。下一步为 PR-003 拆定文件存储、授权下载、文本型 PDF 解析和浏览器上传的任务书。PR-004 基础完成后，问答和卡片/测评可以由不同开发者并行；批改与音频也可在 S5 分人开发。多人协作统一复用资料 ID、版本和学习事件，避免各工具另造一套存储。

**认证边界**：StudyC 通过本机 Clyna 会话接口验证身份，不复制 JWT 密钥或注册服务。历史 PlanPlan 迁移 18 保留；StudyC 核验并接管业务表，以独立迁移登记管理后续变更。后续学习业务 PR 均放 StudyC。

本路线按依赖和完成标准排顺序，不给未经开发者确认的人日或上线日期。后续接手人先确认基线及仓库权限，再对各 PR 估时。PR-001/002 的实现与部署状态见本页开头，后续阶段不因基础接口完成而视为已上线。
