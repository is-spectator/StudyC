# PR-014：一级文件夹与学习集归类

2026-11-24，分支 `codex/studyc-folders`，基于 PR-013（GitHub #14）。仅StudyC业务与本地部署。

## 用户结果和范围

全局侧栏「文件夹」→新建文件夹→打开「未分类」或现有文件夹→选择学习集「移动或归类」→明确保存目标位置。移动后打开目标文件夹，可直接打开原学习集。既有学习集默认未分类；读操作不为它们创建占位写记录。

- 第一版是学习集的一级归类，没有嵌套文件夹、跨账户移动或把资料本身迁到另一学习集。
- 移动仅修改独立归类记录，不改变学习集/资料/卡片/笔记/测验ID、输入版本、来源快照、原文件和学习历史，也不创建副本。
- 同账户有效文件夹名称唯一，忽略普通字母大小写；已删除名称可以明确新建复用，但新容器得到新UUID。
- 文件夹支持改名和删除。删除将其中学习集移到未分类，学习资料与记录保留。第一版没有恢复已删除容器的按钮；原创建请求重试不能复活该容器。
- 学习集可移回未分类。归类有独立版本：未建立过归类记录为0，之后每次保存加一；移回未分类也保留版本，避免旧页面跨往返移动后覆盖新位置。

## 数据、并发与请求恢复

迁移v12 `studyc_folders` 新增 `study_folders`、`study_folder_assignments`、`study_folder_requests`。原业务表/迁移保持不变；复合外键绑定账户、学习集和文件夹，有效账户写守卫及账户删除级联保留。只读分页20条，覆盖目标选择器及容器内学习集。

写操作带clientRequestId；改名/删除带文件夹version，移动带归类version。按账户事务串行，检查版本及目标归属。重复请求返回当前实体或原删除确认，不重新应用曾经完成的旧操作。删除容器与清空其归类在同一事务完成，删除确认的原移动数量可重复核对。

网络结果不明确时冻结输入与普通保存，允许重试同一请求；不能因为再点一次保存生成新意图。409保留本地名称/目标并展示云端状态，用户读入新版本后再明确保存。相同请求ID改载荷409，跨账户/无效对象404。未知字段（包括parentFolderId）拒绝，不会隐式创建层级。

`STUDYC_FOLDERS_ENABLED=false`关闭新建、改名、删除和移动；现有分类与内容仍可查看。回退保留v12表，使用仍识别v12的应用。历史v1～v11校验和、指纹、登记和内容不改写。

## API与代理

同源Cookie、Expected-User、Origin/CSRF、共享写限流、private/no-store；写入JSON最多16KiB。新增5组Nginx路径、8种方法；其他产品代理不变。代理验证测试同时检查每条样例只匹配一个允许规则及全部规则覆盖，不依赖规则排列顺序。

| 路径 | 方法 | 行为 |
| --- | --- | --- |
| `/v1/study/folders` | GET/POST | 20条分页 / `{clientRequestId,title}`创建。 |
| `/v1/study/folders/:folderId` | GET/PATCH | 详情 / `{clientRequestId,version,title}`改名。 |
| `/v1/study/folders/:folderId/remove` | POST | `{clientRequestId,version}`移除容器，原学习集移到未分类。 |
| `/v1/study/folders/:folderId/sets` | GET | 容器内学习集分页；folderId也可为字面值unfiled。 |
| `/v1/study/sets/:setId/folder` | GET/PATCH | 当前归类 / `{clientRequestId,version,folderId:null或UUID}`保存。 |
