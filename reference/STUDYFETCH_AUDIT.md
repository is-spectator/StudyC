## 已确认的产品方向

- 产品名为 **StudyC**；学习助手称“小C”。弱化 K12 与年龄边界，围绕资料、主题和学习目标组织体验。学习阶段可选；保留已有课程示例不代表新建了完整大学或成人课程库。
- **Clyna 统一注册**，StudyC 与 PlanPlan 复用现有账户体系。继续区分共用账户、各站会话与学习业务数据；原站功能实测不验证 Clyna 身份链路，也不是重做注册或迁移账户的授权。
- 外观参考与真实能力分别验收。不要用静态预览、示例题、假进度或“已生成”提示代替可用产物、结果保存和来源关联。

## 后续开发必须明确的领域对象

以下是基于可见行为与 StudyC 缺口整理的**建模建议**，不是已查明的 StudyFetch 数据表、私有 API 或后端实现。

| 对象／边界 | 必须区分的内容 |
| --- | --- |
| 账户与学习集 | 账户身份及权限；独立学习集的稳定 ID、所有权、可见性与内容归属。学习集不能只是多个名字共用同一份资料和成绩。 |
| 资料、来源与版本 | 原文件／输入文本、解析正文、页面或片段定位、材料版本；生成产物必须能说明用了哪份资料和哪段内容。 |
| 单元与主题 | 从资料组织的知识点及计划结构；主题可以关联不同活动，覆盖与掌握不是同一个布尔勾选。 |
| 生成任务与产物 | 来源选择、配置、任务状态、错误、输出版本分别保存；资料 ready、路径构建、生成结束、可播放/可作答是不同阶段。 |
| 学习活动与尝试 | 闪卡组、测验、考试、阅读、辅导、作业、媒体和游戏各有产物；答题尝试、改答、提交、反馈、复习评级与结果属于活动记录。QuizFetch 的纠错掌握与 Practice Test 的最终评分不可共用含混统计。 |
| 高亮、收藏与引用 | 高亮保存源对象、定位及相关内容；收藏是筛选；引用是可回溯来源。它们不等于完成、答对或掌握。 |
| 反馈、进度与计划 | 正确率、信心、SRS 评级/到期、主题掌握、已涵盖、计划进度分别定义；学习事件驱动更新。一次最终100%不能抹去先前错答或产物数量差异。 |
| 日历、媒体与发布 | 日程的时间、时区、重复与计划关联；自己的笔记、转写、增强笔记、音视频对象各自保存。分享/公开菜单状态必须另验访客权限，不能仅凭“Private”标签推断所有权规则。 |

核心链路：**资料 → 主题 → 学习活动 → 反馈 → 进度**。资料选择、产物、每次尝试、来源定位与主题进度应贯通，而非各工具独立返回固定示例。

## 实施优先顺序

1. **独立学习集与后端持久化**：保留既有账户基础，建立稳定业务实体与访问边界，明确本地数据导入、复制、删除及多产物历史；先验同账户不同学习集与不同账户的隔离。
2. **真实文件解析与生成**：保存原文件、解析结果和可定位来源；建立可恢复的异步任务，再接真实生成。错误、重试、用量与终态需可解释。
3. **问答引用、卡片与测评**：从同一真实资料得到可核对的回答和产物，完成编辑、作答、反馈、结果保存及刷新/换设备续做；配置题数与实际产物、结果分母一致。
4. **复习、计划与日历**：基于已保存的学习事件形成复习队列和主题进度；区分手动安排与自动排程，验证重排不覆盖用户内容。
5. **多媒体、批改、游戏与学习工具**：在文件、任务、权限和计量基础上扩展；实际播放、录制/转写、评阅反馈、游戏交互和应用运行各有自己的验收，随后再处理发布、集成与商业化。

首条交付验收：登录 → 建独立学习集 → 导入真实资料 → 查看可溯源内容 → 生成卡片/测验 → 完成学习并保存反馈 → 重开或换设备继续。实现前仍需读取当前代码和相关规则；本研究不提供或猜测可直接调用的原站接口。
